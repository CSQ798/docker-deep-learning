## 必须讲透的内容

1. **可写层的真相**（必须承接第 03 章的写时复制）：
   - 容器里写文件的完整过程：先复制到可写层再修改；
   - 可写层的生命周期与容器绑定，`docker rm` 即消失；
   - 写放大的性能代价：大文件、数据库数据目录放在可写层会明显变慢；
   - 一个反直觉结论：**"容器里能写文件"和"数据安全"是两件事**。
2. **三种挂载方式的本质与取舍**（要给出完整对比表：谁管理、路径形式、典型用途、跨平台行为、性能、能否被 Docker 备份、删除命令）：
   - **数据卷（Volume）**：Docker 管理、位于 Docker 的数据目录、`docker volume create/ls/inspect/rm`、支持只读挂载、跨容器共享、推荐用于生产数据；
   - **绑定挂载（Bind Mount）**：把宿主机具体路径挂进去、开发时热更新利器、依赖宿主机目录结构、容易误写宿主机文件；
   - **tmpfs**：只存内存、容器停即消失、适合临时密钥与缓存。
   - 判断准则：**开发用绑定挂载，生产用数据卷**。要解释为什么这条准则不是教条（什么时候要反过来）。
3. **`-v` 与 `--mount` 两种语法的差异**：`-v` 简洁、`--mount` 更明确（键值对、报错更清楚、支持更多选项）。要给出等价写法对照表，并解释一个经典陷阱：`-v mydata:/app` 与 `-v ./mydata:/app` 的差别（前者是卷，后者是绑定挂载）；以及**当宿主机路径不存在时 `-v` 会静默创建目录**这一危险行为。
4. **容器启动时数据卷的"初始化"语义**：空卷挂到一个非空目录时，Docker 会把镜像里的内容复制进卷一次。这个行为经常被人当作"神秘现象"。要讲清它的规则与后果（以及它为什么会让"改了镜像里的文件但容器里没变"）。
5. **匿名卷与磁盘黑洞**：Dockerfile 里写了 `VOLUME`，或 compose 里只写容器内路径 → 产生随机 ID 的匿名卷；`docker rm` 不删卷、`-v` 才删；这些卷会成为"看不见的磁盘杀手"。要给出检查方法（`docker volume ls -f dangling=true`、`docker system df -v`）。
6. **Windows + Docker Desktop 的真实体验**（对读者极其重要）：
   - 挂载 Windows 目录进容器时，文件同步经过虚拟机边界，性能明显低于 Linux；
   - 文件变更通知（inotify）常常失效，导致前端热更新、Python reload 不工作；
   - 变通方案（把源码放进卷并在容器内安装依赖、使用轮询模式、把项目放进 WSL 文件系统）与各自代价；
   - 路径写法（`${PWD}` 在 PowerShell 里的可用性、`//d/project` 之类的形式、绝对路径的推荐写法）。
7. **备份与恢复**（要给出可复制的完整命令流程）：
   - 用临时容器 + `tar` 打包卷内容到宿主机；
   - 从 tar 恢复到新卷；
   - 迁移卷到另一台机器；
   - 要提醒：**"备份成功"必须通过一次真实的恢复演练来证明**，否则它只是信念。
8. **数据库容器化的正确姿势与常见误区**：
   - 用 `docker run` 起一个 Postgres/MySQL/Redis，把数据目录挂到卷上；
   - 为什么通过环境变量传初始密码、以及"初始化只在数据目录为空时执行一次"这个经典困惑（改了密码为什么没生效）；
   - 为什么"把数据库放进容器"与"数据库不能被容器化"这两个说法都不准确；
   - 有状态服务的清单：备份、升级路径、资源保障、单点问题（第 12 章展开集群中的有状态难题）。
9. **数据生命周期设计**：把应用数据分成三类——**可丢弃的临时数据、需要持久化的业务数据、必须被备份与审计的关键数据**，并说明每一类该放在哪里。这是本章要交付的思维工具。

## 必做实验（≥5，命令真实可跑）
1. 用 `-v` 与 `--mount` 各挂一次，观察 `docker inspect` 里 `Mounts` 字段的差异。
2. 演示数据持久化：`docker run -d --name db -e POSTGRES_PASSWORD=secret -v pgdata:/var/lib/postgresql/data postgres:16`，写入一条数据 → `docker rm -f db` → 用同一个卷重开 → 数据仍在。要写清每一步与预期输出。
3. 演示绑定挂载：把一个本地目录挂进容器，在宿主机改文件、在容器里看到变化。
4. 演示"空卷初始化"现象：先 `docker run --rm -v testvol:/data alpine ls /data` 看是否有内容（用一个镜像里本来就有文件的目录，例如 `-v testvol:/etc/nginx` 配 nginx），并解释。
5. 演示匿名卷的产生与残留：不带名字挂载 → `docker volume ls` 找 dangling 卷 → 清理。
6. 完整做一次备份与恢复演练（导出 tar、删卷、恢复、验证）。
7. 可选：在 Windows 上挂载 D 盘目录跑一个 Python 脚本，感受文件系统性能差异（用 `time` 或简单计时）。
