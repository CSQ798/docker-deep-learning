## 本章必须讲清的核心命题

1. **"在我机器上能跑"到底是怎么产生的？** 要从机理上解释，不要只说"环境不一样"。至少拆到这几层：
   - 程序运行依赖什么：运行时（Python/Node/Java 的版本）、第三方库及其版本、系统库与动态链接（glibc/OpenSSL）、环境变量与配置文件、文件路径与权限、外部服务（数据库、缓存）。
   - 版本冲突：A 项目要 Python 3.8 + numpy 1.x，B 项目要 Python 3.12 + numpy 2.x，为什么不能"各让一步"？
   - 操作系统差异：同一份代码在 Windows、macOS、Linux 上的行为为何不同（换行符、大小写敏感、路径分隔符、进程模型、信号）。
   - 隐性依赖：全局安装的包、手工改过的配置文件、"我电脑上装过某个工具"——**这些从不写进任何文档，也从不被任何人记得**。
2. **软件交付中的四个古老问题**（贯穿全书的四条线索，后面每一章都会回到它们）：
   - 环境不一致（environment inconsistency）
   - 依赖冲突（dependency conflict / 依赖地狱）
   - 交付物模糊（artifact ambiguity）："把项目发给你"到底发什么？源码？压缩包？一堆说明文档？
   - 迁移与扩缩的噩梦：换服务器、加机器时要重复多少手工步骤。
3. **隔离思想的演进史**（要讲成一条有因果的故事线，不能是名词罗列）：
   - 1960s—70s：分时系统与多用户，为什么"隔离"从第一天就是需求。
   - 1979：chroot（改变根目录）——只有文件系统隔离，能做什么、能被怎样轻易逃出去。
   - 1990s—2000s：FreeBSD Jails、Solaris Zones 的思路。
   - 2002：Linux namespace 进入内核；2006—2007：cgroups（最初叫 process containers）。
   - 2006—2008：Google 内部的 cgroups 与 Borg，为什么大规模集群需要它。
   - 2008：LXC 把 namespace + cgroups 打包成"容器"这个概念。
   - 2013：dotCloud 的 Solomon Hykes 在 PyCon 上演示 Docker；为什么这次"同样的技术"忽然成功了——**它解决了分发问题（镜像格式 + 公共仓库），而不只是隔离问题**。这一点非常重要，要在正文中浓墨重彩。
   - 2015 之后：OCI 标准、containerd 捐赠、Kubernetes 胜出——"容器"从一家公司的产品变成整个行业的接口。
4. **容器与虚拟机的本质区别**：共享内核 vs 共享硬件。必须做一张对比表（启动速度、体积、隔离强度、内核限制、能否跑不同操作系统、密度、安全边界、适用场景）。要给出具体数字感受（容器启动数百毫秒级、虚拟机通常数十秒级；镜像几十 MB 与虚拟机动辄数 GB）。
5. **隔离的强度是阶梯，不是开关**：内核共享带来的三个真实后果——(1) 容器不能装一个不一样的内核；(2) 内核漏洞可能成为逃逸通道；(3) 宿主机的内核版本决定了你能跑的容器。呼应第 09 章（安全）。
6. **三个必须被纠正的第一印象**（这是本章的情感高潮之一）：
   - "容器是轻量级虚拟机" —— 错，它根本不是虚拟机。
   - "Docker 就是容器" —— 错，Docker 是打包与分发工具链，容器是内核能力。
   - "有了容器就不用管环境了" —— 错，是把环境**显式写下来了**，而不是消失了。

## 必须包含的动手实验（用真实可跑的命令）

1. **第一个容器**：`docker run hello-world`，让读者读输出，解释每一行在说什么（本地找不到镜像 → 去仓库拉 → 创建容器 → 运行 → 退出 → 打印那封信）。要指出：**这条命令背后已经发生了全书要讲的几乎所有环节**，只是被隐藏了。
2. **"同一个镜像，两个容器，互不干扰"实验**：`docker run -it --name a ubuntu bash` 建一个文件，再开另一个终端 `docker run -it --name b ubuntu bash` 查看该文件不存在。让他解释为什么，并追问：如果它们真的完全隔离，为什么 `docker images` 里只有一个 ubuntu 镜像？
3. **"共享内核"的可验证证据**：在容器里执行 `uname -r`，与在宿主机（或 Docker Desktop 的 WSL2 里）执行 `uname -r` 对比；再看 `cat /etc/os-release` 与宿主机的差异。让读者亲眼看到"内核相同、发行版不同"这一对矛盾现象。这是本章最有冲击力的实验，务必详细写出步骤与预期输出。
4. **可选**：用 `docker run -it --rm alpine sh` 体验一个 5 MB 的系统，感受"没有内核的操作系统"到底有多小。

## 至少 8 个思考题的方向（不限于此，要自己想更好的）

- 如果隔离的强度取决于内核，那么"把两个互相不信任的公司的程序跑在同一台机器上"这件事，在什么条件下是安全的？
- chroot 早在 1979 年就存在，为什么直到 2013 年"容器"才真正流行起来？技术成熟与生态成熟，哪个更关键？
- 假设你是一名 2008 年的工程师，你会怎么向老板解释"把应用装进盒子里"的价值？如果他反问"我们已经在用虚拟机了"，你怎么回答？
- 虚拟机真的会被容器取代吗？找出至少一个容器明显不擅长的场景。
- 如果镜像格式是开放的（OCI），为什么 Docker 公司仍然重要？一家公司把核心技术标准化，是慷慨还是策略？
- "在我机器上能跑"这个问题，容器真的彻底解决了吗？什么情况下它仍然会出现？
- 如果一个容器"共享内核"却"看起来像独立系统"，那么"系统"这个概念到底由什么定义？
