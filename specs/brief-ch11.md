## 必须讲透的内容

1. **为什么 AI 开发者格外需要容器**（要写得有痛感）：
   - Python 生态的版本地狱（torch / tensorflow / numpy / CUDA 之间的版本纠缠）；
   - 复现一篇论文的代码为什么常常失败；
   - 换一台机器、换一张卡就要重新配置几天；
   - 实验结果无法复现的代价（科学上比工程上更严重）；
   - "在我机器上能跑"在 AI 场景里变成了"在我这张卡上能跑"。
2. **CUDA 版本的四层关系**（本章技术核心，必须讲得非常清楚，并配一张层次表）：
   - 第一层：NVIDIA 显卡驱动（装在宿主机，决定最高支持的 CUDA 版本）；
   - 第二层：CUDA 驱动接口（driver API，由驱动提供）；
   - 第三层：镜像里的 CUDA 运行时（runtime，如 `nvidia/cuda:12.4.0-runtime-ubuntu22.04`）；
   - 第四层：深度学习框架（PyTorch/TensorFlow）编译时绑定的 CUDA 版本。
   - 要讲清"向后兼容"的方向性：高版本驱动可以跑低版本 CUDA 运行时，反之不行；
   - 要给出一条实用的排查顺序：先 `nvidia-smi` 看驱动支持的 CUDA 版本 → 再选与之匹配的镜像 tag → 再确认框架版本。
   - **诚实标注**：具体版本号会随时间变化，请以 NVIDIA 官方镜像标签页与 PyTorch 官网的版本矩阵为准，不要死记数字。
3. **GPU 容器实战**：
   - 前置条件（Windows 上需要在 WSL2 里安装合适的 NVIDIA 驱动，`nvidia-smi` 能在 WSL 里跑通）；
   - `docker run --gpus all ...` 与旧式 `--runtime=nvidia` 的区别；
   - 需要 NVIDIA Container Toolkit（Linux）或 Docker Desktop 内建支持（Windows）；
   - 在容器内验证 GPU 可用：`nvidia-smi`、`torch.cuda.is_available()`、`torch.cuda.get_device_name(0)`；
   - 常见失败现象与原因（驱动不匹配、没有 `--gpus`、镜像里没有 CUDA 运行时、WSL 驱动没装对）。
   - 若读者的机器没有 NVIDIA 显卡，**必须给出纯 CPU 的替代路径**（用 `python:3.12-slim` 装 CPU 版 torch），让他依然能完成本章的实验。这一点非常重要，不能让他因为没显卡而丧失学习机会。
4. **交互式开发环境的容器化**：
   - 用官方 `jupyter/` 系列镜像或自建 Jupyter 容器，`-p 8888:8888`、token 的使用与安全提醒；
   - 笔记本目录必须挂载出来（否则容器一删，代码没了）——这里正好回收第 06 章的知识；
   - VS Code 的 Dev Containers 思路（了解即可）；
   - 环境固化：把"我用过的所有包"写进 Dockerfile，而不是靠 `pip install` 手工累积。
5. **训练环境的工程化**：
   - 数据挂载（大数据集不该进镜像，用只读卷或绑定挂载）；
   - 输出与 checkpoint 的持久化（回收第 06 章）；
   - 资源限制与 GPU 分配（`--gpus '"device=0,1"'` 指定卡）；
   - 镜像体积的现实困境（CUDA 基础镜像动辄几个 GB），以及缓解手段（选 runtime 而不是 devel、多阶段、共享基础层）；
   - 记录实验：镜像 digest + 提交哈希 + 超参数 = 可复现的实验身份。**这是本章最有价值的工程观点之一**。
6. **从训练到服务：模型部署与推理服务**：
   - 训练与推理的环境差异（训练要工具链，推理只要运行时）；
   - 用 FastAPI 写一个最小推理服务并容器化（给出一份可用的 Dockerfile 与 app.py 骨架，但不要写成完整教程式的长篇代码，重点是工程决策）；
   - 多阶段构建在 AI 场景的应用（构建依赖 vs 运行时依赖）；
   - 推理服务的容器化考量：并发、批处理、显存管理、冷启动时间、模型版本切换；
   - 量化与蒸馏只是名词了解，不展开算法。
7. **MLOps 全景（了解层次，不求深入）**：数据版本、实验追踪、模型注册、部署、监控漂移、回滚。要说明：**MLOps 本质上是把第 10 章的流水线思想延伸到数据与模型上**。
8. **AI 与容器共同的前沿趋势（点到为止，不预测）**：容器化推理、GPU 共享与切分、模型分发格式。要克制，**不要编造产品名与时间表**。

## 必做实验（≥4，每个都要给出"没有显卡"时的替代方案）
1. 启动一个 Jupyter 容器，挂载本地目录，在浏览器里跑一行 Python，并在容器内验证代码文件出现在宿主机目录里。
2. 自建一个最小 Python 容器并构建（体现第 05 章的多阶段构建）。
3. （有 NVIDIA 显卡时）`docker run --rm --gpus all nvidia/cuda:12.4.0-base-ubuntu22.04 nvidia-smi`，观察输出；若无显卡，改为在容器内打印 `platform` 与 `cpu` 信息，并解释"为什么这里本该有 GPU"。
4. 用 `docker run -it --rm -v ${PWD}:/work -w /work python:3.12-slim bash` 体验"一次性可复现的 Python 环境"，在里面 `pip install` 一个包，退出后确认环境消失——由此理解"环境应该是被声明出来的，不是被累积出来的"。
5. （可选）把一个 FastAPI 应用容器化并 `curl` 验证接口。
